# Тестовое задание ТОЛЬКООПТ

Расчёт рекомендованной цены по предложениям конкурентов. Python 3.10+, только стандартная библиотека.

## Запуск и проверка

```bash
python starter.py
python -m unittest -v
```

Пример имитирует ответ источника с задержкой 0–3 секунды: при своевременном ответе возвращает `4728.00` и `APPLY`, при тайм-ауте — текущую цену `4900.00` и `HOLD`. Реальных сетевых запросов нет.

- [starter.py](starter.py) — реализация `recommend_price` и пример источника.
- [test_starter.py](test_starter.py) — 14 автоматических тестов, включая ошибки и граничные случаи.
- [CHANGES.md](CHANGES.md) — описание изменений и проверяемых правил.

## 1. Вопросы до реализации

1. Какие площадки подключаем и как часто нужно обновлять цены?
2. Есть ли исходники и документация старой системы, как она запускается и можно ли связаться с прежним разработчиком?
3. Как сейчас сопоставляются товары нашего каталога с предложениями конкурентов? Какие особенности нужно учитывать для разных групп товаров?
4. Какое поведение ожидается при недоступности площадки, неполном ответе и повторной обработке данных: сохранять цену, использовать предыдущие данные или останавливать обновление?
5. Кто проверяет спорные рекомендации и каким способом утверждённая цена попадает в клиентский прайс?

Наиболее важны **вопросы 2 и 4**. Доступность исходников и описание старой системы определят способ интеграции, параллельного запуска и возврата к прежнему варианту. Ответ на вопрос 4 позволит согласовать поведение при сбоях заранее: например, текущий код сохраняет цену при неполном ответе, даже если часть предложений получена.

**Допущения:** товары уже сопоставлены; правила расчёта заданы условиями задания; при ошибках сохраняем текущую цену. Хранение результатов и публикацию прайса предлагаю добавить вокруг существующей функции.

## 2. Простая архитектура

Планировщик запускает получение предложений по расписанию. Адаптер каждой площадки приводит её ответ к формату `status` и `offers`, который ожидает `recommend_price`. Полученные предложения, время загрузки и статус сохраняются в SQLite — локальной базе, которой не нужен отдельный сервер. В расчёт передаётся успешный ответ, соответствующий формату данных из задания. Функция исключает собственный магазин и предложения с неизвестной доставкой или доставкой больше шести дней. Затем она уменьшает минимальную подходящую цену на 1,5%, округляет вниз до копейки и учитывает `min_price`. Рекомендация, причина и решение сохраняются в базе: `APPLY` разрешает обновление, `REVIEW` требует ручной проверки, `HOLD` сохраняет текущую цену. Модуль публикации обновляет клиентский прайс по разрешённым рекомендациям и сохраняет предыдущие цены для восстановления.

- **Компоненты, хранение и пригодность данных.** Основные части — планировщик, адаптеры площадок, SQLite, существующая функция расчёта и модуль публикации. Сейчас код хранит результат только в памяти и возвращает словарь. Пригодность определяется успешным статусом ответа и фильтрацией предложений; корректность типов гарантируется условиями задания. Проверку давности данных потребуется добавить после согласования частоты обновления.
- **Недоступность площадки и повторная обработка.** Сейчас функция получает данные через один `fetch_offers`: при исключении, тайм-ауте или статусе `partial`/`error` возвращает текущую цену и `HOLD`. Это предотвращает автоматическое изменение цены по неполному ответу. Повторный вызов заново выполняет расчёт; защиты от повторной публикации пока нет, поскольку сама публикация не реализована. Предлагаю учитывать идентификатор результата и товара, чтобы одно обновление не применялось повторно. Эти правила согласую в вопросе 4, включая возможность расчёта при отказе одной из нескольких площадок.
- **Запуск рядом со старой системой и откат.** После уточнения вопроса 2 сначала запущу новую систему без публикации и сравню её рекомендации с действующим прайсом. Затем включу обновление для небольшой группы товаров. Рабочую версию кода зафиксирую в Git; при проблеме отключу новую публикацию и верну обновление старой системе. Если ошибочные цены уже опубликованы, восстановлю их из сохранённой предыдущей версии прайса: откат кода в Git сам по себе цены не восстанавливает.
