# Изменения starter.py и проверка правил

Использована только стандартная библиотека Python. Интерфейс `recommend_price`
сохранён: параметры и структура результата не изменились. `price` теперь всегда
остаётся `Decimal`. Ниже показаны исходные и новые фрагменты и объяснено назначение изменений.

## 1. Импорты и имитация ожидания

Было:

```python
import asyncio
from decimal import Decimal

async def sample_fetch_offers():
    return {...}
```

Стало:

```python
import asyncio
import random
from decimal import Decimal, ROUND_DOWN

async def sample_fetch_offers():
    await asyncio.sleep(random.uniform(0, 3))
    return {...}
```

В этих фрагментах `{...}` обозначает пропущенный для краткости словарь из файла.
`random.uniform(0, 3)` выбирает случайную дробную задержку от 0 до 3 секунд.
`await asyncio.sleep(...)` приостанавливает функцию, позволяя asyncio выполнять
другие задачи. Это имитация ожидания внешнего сервиса; сетевых запросов нет.
`ROUND_DOWN` нужен для явного округления денег вниз.

## 2. Тайм-аут и ошибка источника

Было:

```python
result = await fetch_offers()
```

Стало:

```python
try:
    result = await asyncio.wait_for(fetch_offers(), timeout=timeout_s)
except asyncio.TimeoutError:
    return {"price": current_price, "decision": "HOLD", "reason": "Источник не ответил вовремя"}
except Exception:
    return {"price": current_price, "decision": "HOLD", "reason": "Ошибка источника предложений"}
```

Раньше параметр `timeout_s` не использовался. Теперь `wait_for` ограничивает
ожидание и при истечении времени запрашивает отмену операции. Для примера с
`asyncio.sleep` это приводит к прекращению ожидания. В общем случае отмена
кооперативная: источник должен позволять asyncio прервать ожидание.

Исключения источника обрабатываются внутри узкого блока получения данных.
Например, `ConnectionError`, `RuntimeError` или `TypeError` из `fetch_offers`
приведут к `HOLD`. Внешняя отмена задачи (`asyncio.CancelledError`) не скрывается:
она не является наследником `Exception` в поддерживаемых версиях Python.

## 3. Проверка статуса

Раньше проверки не было. Добавлено перед обработкой предложений:

```python
if result["status"] != "success":
    return {"price": current_price, "decision": "HOLD", "reason": "Источник вернул неуспешный статус"}
```

При `partial` и `error` цену менять нельзя, даже если источник вернул предложения.
При любом `HOLD` возвращается текущая цена, в том числе если она ниже `min_price`.

## 4. Decimal и фильтрация

Было:

```python
prices = [
    float(offer["price"])
    for offer in result["offers"]
    if offer["delivery_days"] <= 6
]
```

Стало:

```python
prices = [
    offer["price"]
    for offer in result["offers"]
    if offer["delivery_days"] is not None
    and offer["delivery_days"] <= 6
    and offer["seller"].casefold() != "myshop"
]
```

Цена уже приходит как `Decimal`, поэтому преобразование в `float` удалено.
`casefold()` позволяет сравнивать имя магазина без учёта регистра.

`delivery_days=None` — разрешённое контрактом значение, обозначающее неизвестную
доставку. Предложение исключается, а другие предложения продолжают участвовать
в расчёте. Проверка `is not None` выполняется первой: при ложном результате
Python не вычисляет следующее условие и не пытается сравнить `None` с числом.
Ловить здесь `TypeError` и возвращать `HOLD` для всего ответа было бы неверно:
одна неизвестная доставка не делает остальные предложения непригодными.

Дополнительная проверка типов не добавлялась: по заданию формат данных корректен.

## 5. Пустой список

Раньше код сразу вызывал `min(prices)`, который для пустого списка вызывает
`ValueError`. Добавлено:

```python
if not prices:
    return {"price": current_price, "decision": "HOLD", "reason": "Нет подходящих предложений"}
```

Список может быть пустым изначально или стать пустым после фильтрации.
Проверка выполняется до расчёта минимальной цены и до применения `min_price`.

## 6. Скидка, округление и нижняя граница

Было:

```python
price = round(min(prices) * 0.985, 2)
```

Стало:

```python
discounted_price = (min(prices) * Decimal("0.985")).quantize(
    Decimal("0.01"), rounding=ROUND_DOWN
)
price = max(discounted_price, min_price)
```

Коэффициент `0.985` оставляет 98,5% от минимальной цены конкурента.
Все операции выполняются с `Decimal`. `quantize` задаёт два знака после точки,
а `ROUND_DOWN` отбрасывает лишние знаки у положительных денежных сумм.
Например, `100.01 × 0.985 = 98.50985` превращается в `98.50`, а не в `98.51`.
Затем `max` выбирает большую из рассчитанной цены и `min_price`.

## 7. REVIEW и APPLY

Раньше функция всегда возвращала `APPLY`. Теперь перед этим возвратом добавлено:

```python
if abs(price - current_price) > current_price * Decimal("0.30"):
    return {"price": price, "decision": "REVIEW", "reason": "Изменение цены превышает 30%; нужна ручная проверка"}
```

`abs` берёт величину изменения независимо от его направления. Справа находится
30% текущей цены. Строгое `>` означает, что ровно 30% допускается.
Проверка выполняется после применения минимальной цены. `REVIEW` возвращает
рассчитанную рекомендацию, которую нельзя автоматически применять.
Для `APPLY` также обновлён `reason`, чтобы он описывал скидку и нижнюю границу цены.

Начальное описание файла обновлено: оно больше не утверждает, что ошибки
оставлены намеренно, и объясняет случайный результат запуска примера.

## Запуск

Из папки проекта:

```powershell
python starter.py
python -m unittest -v
```

Пример имеет случайную задержку: при своевременном ответе выводит цену
`Decimal("4728.00")` и `APPLY`, при тайм-ауте — `Decimal("4900.00")` и `HOLD`.
Для тестов случайность заменяется управляемыми значениями: тесты не зависят
от того, какое число случайно выпадет при запуске.

## Что проверяют тесты в test_starter.py

Тесты используют `unittest.IsolatedAsyncioTestCase` для асинхронных функций.
`AsyncMock` заменяет источник заданным ответом или исключением. В таблице
перечислены все 14 тестовых методов; некоторые проверяют несколько вариантов
через `subTest`.

| Тест | Проверяемый случай и ожидаемый результат |
| --- | --- |
| `test_original_example` | Исходные три предложения: результат `4728.00`, `APPLY`; свой магазин и доставка 8 дней исключены. |
| `test_own_shop_is_excluded_in_any_case` | Четыре варианта регистра `MYSHOP` исключаются, даже если собственная цена самая низкая. |
| `test_delivery_boundaries_and_unknown_delivery` | Доставка 0 и ровно 6 дней подходит; 7 дней и `None` исключаются без потери подходящего предложения. |
| `test_no_suitable_offers_keeps_price_even_below_minimum` | Пустой ответ, только долгая доставка, только неизвестная доставка или только свой магазин: `HOLD`, текущая цена 4000 сохраняется при минимуме 4500. |
| `test_unsuccessful_status_keeps_current_price` | `partial` и `error`: `HOLD`, несмотря на наличие предложений; текущая цена ниже минимума сохраняется. |
| `test_source_exceptions_keep_current_price` | Источник выбрасывает `RuntimeError`, `ConnectionError` или `TypeError`: исключение не выходит наружу, возвращается `HOLD`. |
| `test_timeout_cancels_waiting_source` | Источник ожидает бесконечно: тайм-аут 0,01 секунды возвращает `HOLD`; проверяется завершение источника через отмену. |
| `test_decimal_rounds_down_to_kopeck` | Сумма `98.50985` округляется до `98.50`; результат сохраняет два десятичных знака. |
| `test_minimum_price_is_respected` | Скидочная цена ниже минимума: рекомендация повышается до `min_price`. |
| `test_change_threshold_in_both_directions` | Проверяются уменьшение и увеличение, ровно ±30%, значения рядом с границей и отсутствие изменения. При текущих 985 границы — 689.50 и 1280.50. Только выход за них требует `REVIEW`. |
| `test_review_uses_price_after_minimum_is_applied` | Именно `min_price` вызывает рост более 30%: возвращается `REVIEW` с рекомендованной ценой 150, а не с текущей 100. |
| `test_caller_cancellation_is_not_hidden` | Внешняя отмена задачи распространяется вызывающему коду, позволяя корректно остановить работу. |
| `test_sample_random_delay_is_awaited` | Генератор задержки вызывается с границами 0 и 3, а выбранное значение передаётся в ожидаемый `asyncio.sleep`. |
| `test_sample_fast_response_and_timeout` | Реальный `sample_fetch_offers` с управляемой задержкой 0 даёт `APPLY`; с задержкой 3 при тайм-ауте 0,05 секунды даёт `HOLD`. |

Общий помощник тестов дополнительно проверяет тип `Decimal`, состав полей
результата, непустую строку причины и единственный вызов источника без аргументов.
Проверки охватывают правила задания и допустимые входные данные; произвольные
нарушения формата ответа намеренно не проверяются, поскольку контракт их исключает.
